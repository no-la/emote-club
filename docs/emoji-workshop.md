# Emote Club エディタ

関連Issue: https://github.com/hukidamari/hukidamari-hub/issues/1

## 現在の実装範囲

`/` で文字・画像を最大16レイヤーまで配置できる、ブラウザ内で完結する試作。現在はPC向けの操作性を先に整えており、モバイルの再設計は後工程。

- 文字・画像レイヤーの追加、選択、前後の並べ替え、複製、削除
- PNG / JPEG / WebPの読み込み（1画像につき5 MiB、1600万画素まで）
- 画像と文字の自動配置、ドラッグ・矢印キー・数値による移動、選択枠の四隅ハンドル・スライダーによるサイズ変更
- 改行、フォント、文字色、縁の色・太さ、影の色・距離・ぼかし
- PixiJSのWebGLフィルターによるGLSLエフェクト（うねうね・ふちが光る・ドット・ずれ）
- 透明・明暗背景、32px / 16px表示での確認
- 左のレイヤー一覧・中央のキャンバス・右の選択対象の設定を分離。全体の効果はキャンバスのツールバーから開く
- 書体見本と、現在の色を押して開くカラーパレット。縁取り・影は常時表示し、座標は詳細設定から開く
- 128×128透明PNGの書き出し（背景・選択枠は含まない）

「画像」から追加したローカル画像は端末内でのみ使用し、アップロードしない。編集データも保存しない。
Discord認証とサーバー内の共有素材のコードを実装済み。「共有素材」から明示的に登録した画像だけをSupabaseへ保存する。実接続にはDiscordアプリ・Supabaseの環境変数とマイグレーションが必要。設定前は共有機能を準備中として表示する。Discordへの絵文字登録も実装済みで、Botの接続設定と作成権限が必要。未接続の機能を成功したように見せるモックAPIは置かない。

## ローカル開発

Node.js 22.13以降とpnpmを使用する。pnpmが未導入の場合は、以下の `pnpm` を `npx --yes pnpm@10` に置き換えて実行できる。`.env.local` に以下を設定する。認証・共有素材の接続手順は [emoji-sharing-setup.md](emoji-sharing-setup.md) を参照。

```dotenv
SITE_URL=http://localhost:3000
```

```sh
pnpm install
pnpm dev
```

http://localhost:3000/ を開く。

ファイル監視の上限（EMFILE）に当たる環境では、次でポーリングに切り替えられる。

```sh
WATCHPACK_POLLING=1000 pnpm exec next dev --webpack --hostname 127.0.0.1
```

検証コマンド:

```sh
SITE_URL=http://localhost:3000 pnpm build
pnpm lint
pnpm exec tsc --noEmit
```

## 構成

- `src/components/emoji/emoji-editor.tsx`: 入力、選択・ドラッグ操作、プレビューと書き出しUI
- `src/lib/emoji/model.ts`: 型付きの文字・画像レイヤー、対象ごとのエフェクト、初期状態
- `src/components/emoji/layer-panel.tsx`: レイヤー一覧、追加・並べ替え・複製・削除、選択対象の文字・画像設定
- `src/components/emoji/editor-controls.tsx`: 共通のスライダーとカラーパレット
- `src/lib/emoji/renderer.ts`: PixiJS描画とPNG出力。ブラウザでのみ動的ロードする
- `src/lib/emoji/wave-filter.ts`: 共通頂点シェーダーと波形フィルター。時間を自動更新せず、位相を固定して静止画を書き出す
- `src/lib/emoji/effect-pipeline.ts`: 対象ごとのフィルター生成・uniform設定・解放。各レイヤーと全体で共用する処理
- `src/components/emoji/effect-editor.tsx`: 対象に依存しない効果の選択・重ねがけ・並べ替え・調整UI
- `src/lib/emoji/effect-filters.ts`: アルファから生成する発光、ピクセル化、RGBチャンネルの水平ずれ

512pxの作業座標で描画し、固定の正方形を128pxに縮小する。位置調整の数値は出力画像の128px座標で表示する。文字は描画領域に収まるよう初期サイズを調整し、その後にユーザー指定の倍率を適用する。サイズ計算はレイヤーごとに独立し、ほかのレイヤーを追加・削除しても既存レイヤーの大きさを変えない。

Dela Gothic OneはGoogle Fontsの配布ファイルを改変せず同梱。ライセンスと著作権表記は `public/fonts/dela-gothic-one/OFL.txt`。ゴシック体・明朝体の選択肢は端末のシステムフォントなので見た目は端末により異なる。

## 認証・共有素材

ログインしたユーザーが参加中のDiscordサーバーを選択する。素材・登録履歴・容量枠はサーバー単位。読み取りの所属確認は最大60秒再利用し、登録・変更・削除時は必ず再確認する。共有素材の配信には5分間有効の署名付きStorage URLを利用する。

接続設定・権限・容量・復旧手順は [emoji-sharing-setup.md](emoji-sharing-setup.md) に集約する。

## ページレイアウト

`/` がエディタ。ヘッダーにサービス名、サーバー選択、Discordアカウント、サーバー登録、PNG保存を表示する。

エディタは100dvhのシェル内で専用ヘッダーと残りの編集領域をflex配置する。PCでは左260pxに常設の共有素材一覧（上）とレイヤー一覧（下）、中央に可変幅のキャンバス、右310pxに設定欄を置く。ページ全体をスクロールさせず、一覧と設定をそれぞれ内部スクロールにする。モバイル対応はPCの構成が固まった後に再設計する。

### エフェクト

各レイヤーと全体に、それぞれ複数の効果を重ねて適用できる。`model.ts` の `EFFECTS` に表示名と調整項目を集約する。各対象が持つ `EffectStack` の `effects` 配列が適用順を表し、効果ごとの強さ・位相・向き・色は `effectSettings` に独立して保持する。

- うねうね: 指定した向きへの波形変形。強さ、向き（0〜360°）、波の位置を調整。
- ふちが光る: 輪郭の外側に光を付ける。光の広がりと色を調整。初期色は暖色、スウォッチと任意の色を利用できる。
- ドット: 作業座標に固定したグリッドでピクセル化。粗さを調整。
- ずれ: 赤・青チャンネルを指定した向きへずらす。ずれ幅と向き（0〜360°）を調整。

「効果を追加」メニューから未適用の効果を選び、適用したものだけ設定欄に並べる。各行の解除ボタンで外せる。設定欄は適用順に並び、上下ボタンで順序を変更できる。2つ以上適用中なら見出しの一括解除ボタンで、その対象だけを解除できる。オフにしても調整値を保持し、再度オンにすると強さ・向き・色を復元する。強さ0の効果はフィルター列から除外する。透明部分は透明のまま扱い、発光とRGBずれはpremultiplied alphaで合成する。フィルター領域は固定の512px座標とし、内容の大きさが変わってもグリッド・波長を安定させる。適用後も128pxの出力枠の外側は切り取る。

追加時にego-browserで全効果のPNG保存、128pxサイズ・透明な隅、強さ0で無加工と同一になること、390×844画面内への収まりを確認。重ねがけ対応時は4効果の同時適用、順序変更による描画の変化、各強さの独立・再有効化時の復元、一括解除で元のPNGに戻ることも確認。向き・色の追加時は、うねうねとRGBずれの角度変更による描画の変化、青い光でのPNG保存、オフ・オン後の角度・色の復元、スマホ表示も確認。

### キャンバス上のサイズ変更

選択中の文字・画像に四隅のハンドルを表示する。マウス・タッチのドラッグで縦横比を維持し、反対側の角を基準に20〜200%の範囲で拡縮する（中心位置は作業領域内に制限）。ハンドルは常にオブジェクトの実際の四隅に置き、キャンバス端へ押し戻さない。描画はキャンバス内で切り取り、選択枠とハンドルは周囲の余白まで表示する。プレビュー領域から出た操作部品は切り取り、他の設定欄への重なりを防ぐ。設定欄の倍率も連動する。

ハンドルにフォーカスして上・右で1%拡大、下・左で1%縮小。Shift併用は10%。選択枠・ハンドルはDOMの操作部品で、PNGには含めない。

文字のドラッグ縮小で反対側の角と縦横比が保持されること、倍率の同期、キーボード調整、画像のドラッグ拡大・タッチ縮小、保存PNGと390px幅での表示を元プロジェクトでego-browserを使用して確認。

### 文字の影

文字の設定欄で、影の色・距離・ぼかしを独立して調整する。色はスウォッチと任意の色を選べる。距離・ぼかしはそれぞれ0〜24で、どちらも0の場合は影なし。距離0・ぼかしありの場合は中央から広がる影を描画する。不透明度0.65・右下45°は固定。

ego-browserで色・距離・ぼかしそれぞれの変更によるPNGの差、距離0でのぼかし、距離・ぼかし0で元のPNGに戻ること、スマホ画面への収まりを確認。

### 配置のスナップ

文字・画像の移動ドラッグ中、選択枠の左・右・上・下を対応するキャンバス端へ、枠の縦横中央をキャンバス中央へ吸着させる。判定距離は表示上の6pxで、プレビューの表示倍率に合わせて作業座標へ変換する。各軸で最も近い候補を採用する。判定にはドラッグ開始時の選択枠を用い、描画更新の遅れで吸着位置が揺れないようにする。

一致した軸にガイド線を表示し、ドラッグ終了・キャンセル時に消す。Shiftを押している間はスナップを解除する。拡縮・矢印キー・数値入力には適用しない。ガイド線はDOMの操作表示で、PNGには含めない。

文字の上下左右・縦横中央へのスナップ（表示誤差0.01px未満）、Shiftでの解除、画像のタッチスナップ、終了時のガイド消去、保存PNGにガイドが入らないこと、390×844画面への収まりを元プロジェクトでego-browserを使用して確認。

### レイヤー

`EmojiDraft.layers` は奥から手前の順。各レイヤーは安定したIDと種類、位置・倍率を持つ。文字は内容・書体・色・縁取り・影を独立して保持する。画像はブラウザ内でデコードした `HTMLImageElement` とファイル名を持つ。保存用のシリアライズは未実装。

一覧は上が手前。文字・画像を追加すると手前に置き、そのレイヤーを選択する。上下ボタンで一段ずつ手前・奥へ移動する。複製は元の直前（手前）に置き、見分けられるよう位置を16作業pxずらす。削除後は隣接レイヤーを選択し、すべて削除したときは未選択・PNG保存不可になる。追加・複製は最大16個。画像の読み込み中は追加・複製を一時無効にする。

画像の変更は選択レイヤーだけを差し替え、位置・倍率・順序は維持する。複製画像は同じ画像ソースとGPUテクスチャを共有し、どちらかを差し替えてももう片方に影響しない。使われなくなった描画オブジェクト・テクスチャは描画更新時に解放する。

キャンバスの選択判定も描画と同じ前後順。隠れたレイヤーは一覧から選べる。選択枠・拡縮・スナップ・矢印キー・座標入力は各IDのレイヤーに適用する。レイヤー別の効果を適用して合成した後、全体エフェクトを適用する。「自動配置」はレイヤー数に応じたグリッドへ再配置する。自動配置を押すまでは既存の位置を変えない。

レイヤー対応時にego-browserで、文字・色・フォントの独立、前後の入れ替えによるPNGの変化と復元、文字複製後の独立編集、画像複製・差し替え・共有画像の片方削除後の描画、自動配置、全体エフェクトの重ねがけとPNG保存、選択レイヤーの拡縮・タッチスナップ、全削除・空文字の出力禁止・再追加、16個での追加制限、390×844画面への収まりを確認。

### レイヤー別の効果

左のレイヤー一覧から対象を選ぶと、右に文字・画像の設定と適用中の効果をまとめて表示する。編集中の対象名は右欄の固定見出しで確認できる。見た目と効果を切り替えるタブは置かない。効果付きのレイヤーは一覧に印を付ける。全体エフェクトはキャンバスの「全体の効果」から同じ右欄へ開き、見出しで対象を明示する。

各レイヤーと全体は独立した `EffectStack`（効果の順序・設定値）を持つ。複製時は効果の設定もコピーし、複製後の変更は元に影響させない。個別解除・一括解除は表示中の対象だけに適用する。画像の差し替えはそのレイヤーの効果を維持する。

描画は `レイヤーごとの効果 → 前後順に合成 → 全体の効果`。対象ごとに独立したフィルターインスタンス・uniformを持ち、必要になった効果だけを生成する。レイヤー削除時・エディタ終了時に解放する。フィルター領域は作業座標の512pxで固定する。Pixiの `filterArea` は対象コンテナのローカル座標なので、レイヤーごとに変形を持たない親コンテナへ適用し、その子の文字・画像だけを移動・拡縮する。

レイヤー効果の追加時に、PNGの上下領域の比較で非対象レイヤーが変わらないこと、同じ光エフェクトでも対象ごとに色が独立すること、全体効果の追加・解除で個別効果が保たれることを確認。最終UIでも、レイヤー切り替え時の編集モード維持、複製後の独立編集、フィルター付き画像の複製・片方削除、全レイヤー削除時の出力禁止、移動・拡縮後に光エフェクトで文字本体が欠けないこと、スマホでの対象名の追従表示と画面への収まりを元プロジェクトでego-browserを使用して確認。

### PCの情報整理

レイヤー管理と選択対象の編集を別カラムへ分離し、レイヤー数や設定スクロールに関係なく一覧から対象を切り替えられるようにする。フォントはラベルと選択ボタンを1行に配置する。

色の設定は現在色の見本を表示し、押すとnative Popoverでパレットを開く。色の選択で閉じ、任意の色はカラーピッカーから指定する。Escape・外側クリックでも閉じ、スクロールやウィンドウのリサイズ時は古い位置に残さず閉じる。色、影、縁取り自体の設定項目は常時見える。

効果は未適用の候補を追加メニューへ集約する。適用中の設定だけを表示し、順序・強さ・向き・色・解除をその場で操作する。解除後も調整値は保持する。

ego-browserで1200×668・1024×768・1440×900のPC表示を確認。ページ全体をスクロールさせず、文字入力・縁取り・影・効果追加を初期表示から操作できること、設定をスクロールしても左の一覧が動かず、対象を切り替えると右欄が先頭へ戻ることを確認した。色選択後・Escape・外側クリック・設定欄のスクロールでパレットが閉じること、フォント変更、文字の複製・並べ替え・削除、画像の追加・差し替え、全体効果の追加・順序変更・一括解除とレイヤー効果の維持、128×128透明PNGの保存も確認。今回モバイルは検証対象外。


## サーバーへの絵文字登録（2026-10-18追加）

ヘッダーに「サーバーに追加」を設置。ダイアログを開いた時点の描画済みPNGを固定し、名前と登録先サーバーを確認して登録する。PNG保存は従来どおり利用できる。

登録はDiscordの絵文字作成権限を持つメンバーに限定する。APIで所属・権限・Origin・画像を検証し、Bot TokenでDiscordへ直接送信。サーバー選択やebifry連携は追加しない。登録状態をDBに記録し、二重送信・結果不明時の自動再試行を防ぐ。

設定・DBマイグレーション・結果不明時の復旧手順は `docs/emoji-sharing-setup.md` の「Discordサーバーへの絵文字登録」を参照。Bot未設定時も確認ダイアログで準備中と表示する。実登録にはBotの設定・招待と追加マイグレーションが必要。

登録成功後は「閉じる」だけを表示する。閉じると完了した登録状態と名前をリセットし、次に「サーバーに追加」を開くとその時点の編集画像で新しい登録を開始する。処理中・結果不明・失敗の状態は閉じても保持する。


## 常設の共有素材とキャンバス共有

共有素材は左パネル上部に最初から表示し、ログイン後に自動で一覧を取得する。2列のサムネイルをクリックすると画像レイヤーを追加し、素材一覧は開いたままにする。共有素材とレイヤー一覧は別々に内部スクロールする。名前変更・削除は各素材の管理メニューから操作する。

「画像を登録」はローカルのPNG/JPEG/WebP、「今の画像を共有」は描画済みの128×128透明PNGを選択する。どちらもプレビューと素材名を確認するダイアログを開き、「サーバーに共有」を押したときに初めてアップロードする。キャンバス共有はクリック時点の描画を固定する。背景の確認色、選択枠、ガイド、エディタの操作欄は画像に含めない。文字・画像・レイヤー効果・全体効果を合成した画像であり、再編集用のレシピ保存ではない。

描画・フォント読み込みが完了していない場合や空のキャンバスは共有不可。登録後は一覧の先頭に表示する。既存の共有画像APIと同じ所属・Origin・容量・画像検証を使う。ログアウト/ユーザー切替時は共有一覧と未送信の画像をリセットし、編集中のレイヤーは維持する。

常設パネル変更時の型チェック・lint（既存警告8件のみ）・本番ビルド/postbuild・共有機能テスト11件は成功。未ログイン時の常設表示をブラウザで確認。新しいキャンバス共有の実登録とログイン後の一覧操作は、操作用ブラウザのDiscordログイン後に確認する。
